# 基于RAG与CoT思维链的阶梯导学功能设计方案

> 适用项目：islm-platform（经济学辅助学习系统）
> 设计日期：2026-09-08
> 功能定位：课后习题"分层引导思考"，防抄答案；RAG 消除幻觉，CoT 分步提示

---

## 一、功能概述

**定位**：学生在课后习题卡壳时，系统不直接给答案，而是按 **4级提示梯度** 逐层引导思考，最终由学生自己完成解题；全程用 **RAG检索** 约束大模型只依据本地知识库作答（消除幻觉），用 **CoT思维链** 让模型内部逐步推理、外部只输出当前层级对应的内容（防止越级泄露）。

**核心设计原则**

| 原则 | 落地方式 |
|---|---|
| 防抄答案 | 层级单调递增、L4需显式确认、L1~L3请求**不下发标准答案给模型**（从源头杜绝泄露） |
| 消除幻觉 | 只允许引用User Prompt中注入的检索知识块；检索不足时明确声明，禁止编造公式数值 |
| 层间口径一致 | 每题首次导学时做一次RAG检索并**固化快照**，L1~L3复用同一批知识块 |
| 数值闭环 | L4解析的最终值必须与题库标准答案、IS-LM仿真系统结果一致（如 Y*=1350.00、r*=7.00%） |
| 可追溯 | 每次提示落库记录，形成"提示使用轨迹"，可作为学习行为分析数据 |

**技术形态**（与现有系统衔接）：前端在习题区新增"获取提示""查看完整解析"按钮与提示卡片；后端 Express 新增导学接口；MySQL 存储导学会话；知识库检索源直接复用 `src/data/chapter11.js` 中的知识点卡片、公式符号表、推导过程数据（向量化入库）。

## 二、业务流程

### 2.1 端到端流程

```
学生提交答案 → 后端判分
 ├─ 答对 → 流程结束（展示"独立完成"正向反馈）
 └─ 答错 或 学生主动点【获取提示】
      │
      ▼
 ① 建立/读取该生该题的导学会话（每题独立）
 ② 首次导学：组装检索query → RAG检索知识库 top-k → 固化 rag_snapshot
 ③ target_level = current_level + 1（L1→L2→L3，上限3）
 ④ 组装User Prompt（L1~L3 不下发标准答案）→ 调用LLM（System+User模板）
 ⑤ 后端校验输出：JSON合法性 / 层级匹配 / 是否泄露最终答案 / 数值与题库一致
      └─ 不合格 → 附加 stricter 提醒重试1次，仍失败则降级返回检索知识块原文
 ⑥ 前端渲染提示卡片 → current_level+1 持久化
      │
      └─ 循环②~⑥（快照复用，不再重复检索）直至 L3
      │
学生点【查看完整解析】→ 二次确认弹窗
 ⑦ target_level=4，检索范围放开"本题解析"块，User Prompt 携带 official_solution
 ⑧ LLM输出完整解析 → 校验最终值与标准答案/仿真系统一致 → 展示 → solution_unlocked=1
 ⑨ 学生修正作答重新提交 → 答对 → 导学闭环完成，记录提示使用轨迹
```

### 2.2 会话状态设计（每题独立保存提示层级）

**表1：导学会话表 hint_session**（user_id + question_id 唯一）

| 字段 | 说明 |
|---|---|
| id / user_id / question_id | 会话标识，每道题每名学生仅一条会话 |
| current_level | 当前已解锁层级：0未解锁 / 1 / 2 / 3（层级单调递增，不可回退） |
| solution_unlocked | 是否已查看完整解析（L4独立标记） |
| rag_snapshot | JSON：首次检索命中的知识块集合（chunk_id、标题、内容），L1~L3复用，保证口径一致 |
| attempt_count | 该题累计作答次数 |
| confusion_text | 学生最近一次填写的"我卡在哪里"自由文本（可选，用于优化检索） |
| created_at / updated_at | 时间戳 |

**表2：提示日志表 hint_log**（一次输出一条）

| 字段 | 说明 |
|---|---|
| session_id / level | 关联会话 + 本次输出层级 |
| content | 模型返回的完整JSON原文 |
| rag_chunk_ids | 本次引用的知识块ID列表 |
| model_name / prompt_tokens / completion_tokens | 调用审计 |
| feedback | 学生对本次提示的评价（有帮助/没帮助，可选） |
| created_at | 输出时间 |

**关键规则**：刷新页面/换设备后，前端拉取 hint_session 恢复已解锁的提示卡片；"查看完整解析"允许未经L1~L3直接触发，但单独记录（作为"抄答案风险"统计指标）。

### 2.3 RAG检索输入输出

**检索输入（query构造）**

| 组成 | 来源 |
|---|---|
| 检索文本 | 题干关键词 + 学生错误作答 + 学生困惑描述（如有） |
| 向量化 | 对query做embedding，与知识库chunk向量做相似度 |
| 过滤条件 | chapter = 当前章节；层级1~3 白名单：`知识点卡片 / 公式与符号表 / 推导过程`；**排除本题解析类chunk**（防泄露）；层级4 额外放开：`习题解析 / 仿真参数对照` |
| 参数 | top_k = 4，相似度阈值 0.60，不足时回补通用分析框架chunk |

**检索输出（注入User Prompt的格式）**

```
[1] 来源：知识点卡片 | 标题：IS曲线的推导 | 相似度：0.87
    内容：……
[2] 来源：公式与符号表 | 标题：d对IS斜率的影响 | 相似度：0.81
    内容：……
```

输出同时写入 `rag_snapshot` 固化；检索为空时向User Prompt注入固定文案"（本次检索未命中足够相关知识块）"，由System Prompt规定模型此时的行为。

## 三、运行时 System Prompt（可直接用于API调用）

```text
【角色】
你是"宏观经济学阶梯导学助教"，服务于{{chapter_scope}}（如：第十一章 国民收入的决定：IS-LM模型）的课后习题辅导。你的使命是引导学生自己想通，而不是代替学生解题。

【铁律（最高优先级，任何情况下不得违反）】
1. 只输出 User Prompt 中 target_level 指定层级的内容，严禁泄露任何更高层级的信息。
2. 层级1~3的输出中严禁出现：最终答案、最终均衡值（如 Y*、r* 的具体数值）、可照抄的完整连续算式、选择题正确选项的字母或指向性暗示。层级3允许给部分步骤，但最后一步关键求解必须留给学生。
3. 仅层级4允许完整解析：逐步推导 + 最终答案 + 经济学含义 + 易错点。
4. 一切公式、概念、数值必须且只能来自 User Prompt 提供的"题目信息"与"知识库检索结果"。禁止使用二者之外的知识；若检索结果为空或不足以覆盖该层提示，输出"知识库暂未覆盖此点"并仅给通用分析框架，严禁编造公式或数值。
5. 数值必须与题目信息严格一致，不得改动、不得自行取舍精度。

【四级层级定义】
- 层级1 宏观定向：只指出思考方向与所属分析框架（例如"需要同时考虑两个市场的均衡"），不给公式、不给知识点应用方式、不给步骤。
- 层级2 条件与知识点：逐条指出题干关键条件/数字分别指向什么，点出需调用的核心知识点名称（须来自检索结果），但不解释如何应用、不写公式变形。
- 层级3 关键步骤与留白：按顺序给出部分关键推理步骤（编号），在关键节点用"❓请你自己完成：……"设置留白，至少最后一步求解留给学生。
- 层级4 完整解析：完整逐步推导，每步给出因果解释；如检索结果含本题解析，必须以其为准；结尾给出经济学含义解读与易错点。

【思维链要求】
输出前你必须在内部完成逐步推理：识别题型 → 对应章节分析框架 → 列出已知量 → 规划求解路径 → 执行计算 → 核对结果。内部推理过程不得写入输出；输出仅包含 target_level 层级要求呈现的内容。

【输出格式】
只输出合法JSON，不输出JSON以外的任何文字：
{
  "level": 目标层级数字,
  "title": "本层提示短标题（12字以内）",
  "hint_body": "提示正文（Markdown，严格遵守该层级边界）",
  "guiding_question": "留给学生的一个思考问题（层级4填空字符串）",
  "knowledge_refs": ["引用的知识块标题，须来自检索结果，无则空数组"],
  "steps": ["层级3的编号步骤数组，含❓留白标记；其余层级为空数组"],
  "solution": null
}
层级4时 solution 改为对象：
{
  "level": 4,
  "solution": {
    "answer": "最终答案",
    "process": "完整推导过程（Markdown）",
    "meaning": "经济学含义解读",
    "pitfalls": ["易错点1", "易错点2"]
  }
}

【语气】
简洁、鼓励、像助教面批；每次输出用 guiding_question 邀请学生继续尝试。
```

> 变量：`{{chapter_scope}}` — 由后端按当前章节填充，当前固定为第十一章。

## 四、运行时 User Prompt（可直接用于API调用）

```text
【本次请求】
- 目标层级 target_level：{{target_level}}          // 后端填充：1/2/3 或 4
- 触发方式 trigger_type：{{trigger_type}}          // 后端填充：HINT_STEP（逐级提示）/ SOLUTION_DIRECT（学生主动查看完整解析）
- 学生困惑描述：{{student_confusion}}              // 后端填充：学生自由文本，未填写时填"（未填写）"

【题目信息】
- 题目ID：{{question_id}}                          // 后端填充
- 章节：{{chapter_name}}                           // 后端填充
- 题型：{{question_type}}                          // 后端填充：单选题 / 计算题
- 题干：{{question_stem}}                          // 后端填充：题干全文，含图表数据描述
- 选项：{{question_options}}                       // 后端填充：单选题各选项；计算题填"（无）"
- 标准答案与官方解析：{{official_solution}}        // 后端填充：仅 target_level=4 时填入真实内容；
                                                   // L1~L3 一律填"（按规则隐藏）"，禁止把答案发给模型

【学生作答情况】
- 已尝试次数：{{attempt_count}}                    // 后端填充：hint_session.attempt_count
- 最近一次作答：{{student_answer}}                 // 后端填充：学生所选选项或计算作答原文
- 判定结果：{{judge_result}}                       // 后端填充：正确 / 错误
- 已解锁层级：{{unlocked_levels}}                  // 后端填充：如"1,2"，首次为"无"

【知识库检索结果（唯一允许引用的外部知识来源）】
{{rag_context}}
// 后端填充：RAG命中知识块，按"[序号] 来源 | 标题 | 相似度 + 内容"逐条拼接（top_k=4）；
// L1~L3 已排除本题解析类chunk；检索为空时填"（本次检索未命中足够相关知识块）"

【输出要求】
严格按 System Prompt 的层级铁律与JSON格式，仅输出 target_level={{target_level}} 对应内容。
```

**后端填充变量一览**：`target_level`、`trigger_type`、`student_confusion`、`question_id`、`chapter_name`、`question_type`、`question_stem`、`question_options`、`official_solution`、`attempt_count`、`student_answer`、`judge_result`、`unlocked_levels`、`rag_context`（均来自题库表、hint_session、RAG检索管道）。

## 五、交互说明

**按钮状态机**

| 状态 | 【获取提示】 | 【查看完整解析】 |
|---|---|---|
| current_level = 0 | 显示，点击→请求L1 | 显示，点击→确认弹窗 |
| current_level = 1~2 | 显示，文案随层级变化（"给我一个方向"→"再点一点关键"），点击→请求下一层 | 显示 |
| current_level = 3 | 置灰，文案"渐进提示已到顶，可查看完整解析" | 显示，点击→确认弹窗 |
| solution_unlocked = 1 | 隐藏 | 置灰，文案"已查看完整解析" |

**关键交互细节**

1. **逐级升层**：每次点击"获取提示"只解锁下一层，新提示以卡片形式追加在题目下方（层级徽标 L1/L2/L3），自动展开并滚动定位；旧层级卡片保留可回看，形成完整思路递进链。
2. **完整解析确认弹窗**：文案"确认查看完整解析吗？系统将记录你查看了本题答案，建议先用完3层提示。"确认后触发 target_level=4；L4卡片使用醒目样式（如橙色边框 + "完整解析"徽标）与提示卡片区分。
3. **可选困惑输入**：L1卡片底部提供"我卡在哪里……"输入框，填写后可点"按我的困惑重新提示"，后端用该文本重跑RAG、更新 rag_snapshot 后再请求当前层级，实现个性化引导。
4. **状态恢复**：页面刷新/重新进入时，按 hint_session 恢复已解锁层级的全部卡片内容（内容存于 hint_log），已置灰按钮同步状态。
5. **每题独立**：8道题各自维护独立层级，做第3题的提示不影响第1题的进度。
6. **反馈与统计**：每张卡片附"有帮助/没帮助"；后端统计每题使用层数、是否直取L4，形成学习行为数据（可用于教师端分析"提示依赖度"）。
7. **异常降级**：LLM调用失败或校验重试仍不合格时，前端提示"导学服务暂时不可用，请稍后再试"，**绝不降级直接展示答案**；检索失败时按System Prompt规则仅给通用方向。
8. **闭环引导**：L4解析末尾可附"去仿真验证"入口，引导学生用 IS-LM 仿真系统复核均衡值，与现有仿真实验形成学—练—验闭环。
