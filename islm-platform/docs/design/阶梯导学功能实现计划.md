# 阶梯导学功能实现计划（RAG关键词检索 + 豆包LLM + Express/MySQL）

## 一、背景与目标

项目 islm-platform（Vue3+Vite+Element Plus 纯前端）已有一份完整的《阶梯导学功能设计.md》（项目根目录）。本计划把设计落地为可运行代码：学生在第11章课后习题卡壳时，点击【获取提示】逐级解锁 L1→L2→L3 提示，【查看完整解析】独立触发 L4；后端用**关键词RAG**检索 chapter11.js 知识库、调**豆包（火山方舟 Ark API）**生成提示，L1~L3 不向模型下发标准答案，防抄答案。

**用户已确认的决策**：后端 Express + MySQL（server/ 目录建在项目内）；RAG 用关键词检索（不用 Embedding）；仅改第11章习题区（Chapter11View.vue），不动 ExerciseView；无登录态，前端 localStorage 生成稳定 userId。

## 二、探索核实结论（影响实现的关键事实）

1. **chapter11.js:19 有 `import { DEFAULT_PARAMS } from '@/constants/presets'`** —— `@/` 别名 Node 无法解析。改为相对路径 `../constants/presets.js`（前端行为不变），后端即可直接 `import` 复用该文件做 RAG 源，避免数据双份维护。
2. **知识正文内嵌答案数值**：第三节 derive 块含 1266.67/5.33%（第6题答案）、图D 含 1433.33/8.67%（第7题）、图G 含 1600/2%（第8题）、第二节 keypoint 含 4.76%/15.8%（第2题解析）。因此 L1~L3 检索池除排除"习题解析"类 chunk 外，**必须再加数值泄露闸**。
3. **习题主数据源是 `chapter11.exercises`**（id 1~8，Chapter11View 实际使用）；questionBank.js 中 id 1~8 是副本且多出 `steps` 字段（`{f, note}` 数组）——L4 组装官方解析时用 questionBank 补 steps。计算题 `answer.r` 为小数（0.0533），前端输入框按百分数填（5.33）。
4. vite.config.js 无 proxy；src/api/islm.js 的 axios 实例未导出且 timeout 短 → 前端新建独立 `src/api/hint.js`（timeout 30s，LLM 生成慢）。
5. storage.js 已有 `loadLocal/saveLocal/genId` 可直接生成持久化 userId；Chapter11View 习题卡片区在 L120-197，exState[ex.id] 含 {choice, y, r, done, correct, showAnalysis}，HintPanel 插入点在其后。
6. 根 package.json 已是 `"type": "module"`，server 端直接写 ESM；ESM 相对导入必须带 `.js` 扩展名。

## 四、后端 API 契约（要点）

统一响应 `{ success, code, message, data }`；code：OK / PARAM_ERROR / QUESTION_NOT_FOUND / LEVEL_LOCKED / LLM_ERROR / DB_ERROR；降级走 200 + `data.degraded:true`。

- **POST /api/hint**：body `{userId, questionId(1~8), confusionText?, studentAnswer?, judgeResult?}`。正常：level=current+1（上限3），返回 `{level, title, hintBody, guidingQuestion, steps[], knowledgeRefs[], degraded, currentLevel, solutionUnlocked, isNew}`。带 confusionText 时重跑检索更新 rag_snapshot 并按当前层级重生成（CONFUSION_RETRY，不递增）。current=3 时返回 LEVEL_LOCKED。LLM 两次失败 → 502 LLM_ERROR（绝不返回答案）。
- **POST /api/hint/solution**：body `{userId, questionId, confirm:true}`（confirm 兜底防绕过弹窗）。允许未解锁 L1~L3 直接调（统计"直取答案"）。幂等：已解锁则回放已有 L4 日志不重调。返回 `{level:4, solution:{answer, process, meaning, pitfalls[]}, ...}`；校验 answer 必须含标准答案数值/正确选项字母，不合格重试1次，仍不合格 degraded 直出题库 analysis+steps 原文（L4 降级给官方原文是安全的）。
- **GET /api/hint/state?userId=**：一次返回该用户全部8题 `{sessions: {"6": {currentLevel, solutionUnlocked, attemptCount, logs[{id, level, degraded, createdAt, content(已parse)}]}}}`，无会话则 `{}`；前端刷新恢复唯一数据源。
- **POST /api/hint/feedback**：`{userId, questionId, hintLogId, feedback:'up'|'down'}`。

**变量填充规则**（hintService）：`official_solution` **仅 L4 填真实内容**（单选：正确答案字母+analysis；计算：Y*/r* + analysis + questionBank.steps），L1~L3 一律"（按规则隐藏）"——从源头防泄露；`question_options` 下发全部选项（选项本身不是答案）；计算题 studentAnswer 的 r 需 ×100 转百分数口径再给模型。

## 五、MySQL（server/sql/init.sql）

- `hint_session`：id, user_id VARCHAR(64), question_id INT, current_level TINYINT(0~3 单调递增), solution_unlocked TINYINT(1), rag_snapshot JSON, attempt_count INT, confusion_text VARCHAR(500), created_at/updated_at；UNIQUE(user_id, question_id)
- `hint_log`：id, session_id, user_id, question_id, level(1~4), trigger_type(HINT_STEP/SOLUTION_DIRECT/CONFUSION_RETRY), content MEDIUMTEXT(校验后的JSON串), rag_chunk_ids JSON, model_name, prompt_tokens, completion_tokens, degraded TINYINT(1), feedback, created_at
- db.js 启动时读 init.sql 逐条执行（幂等建表），学生只需先手动执行一次建库。

## 六、RAG 关键词检索设计

- **分词**（dictionary.js + retriever.js）：去HTML→全角转半角→词典按长度降序贪心最长匹配（先"流动性陷阱"6字后2字词，命中即摘除防止"货币"吃掉"货币需求"）→剩余中文串切 2-gram 过滤停用词→英文/数字/符号串整体成 token（Y*、1266.67、0.8、M/P 是强信号）。
- **chunk 生成**：每个 h4 小标题单元=1 chunk（content 拼接 p/ul/keypoint/formula/derive各步/symbols各项/chart说明），type 判定：含derive→'公式推导'、含symbols→'符号说明'、含formula→'公式讲解'、其余→'知识点讲解'；exercises 每题1个 type='习题解析' chunk；2个通用框架兜底 chunk。
- **L1~L3 检索池两道闸**：① 排除 type='习题解析'；② 数值闸——chunk.text 命中该题任一泄露 token 则剔除（解决知识正文内嵌答案问题）。
- **打分**：简化 TF-IDF，`score = Σ idf(t)×min(tf,3)×(命中标题?2:1) / queryToken数`，阈值 0.15，top-k=4，命中<2 补兜底chunk，每块 content 截断600字。
- **快照复用**：首次导学检索结果整体写入 rag_snapshot，L2/L3 直接复用不重检；带困惑文本时重检并覆盖。

## 七、防泄露校验（leakGuard.js）

1. 每题预计算泄露 token：计算题收集 Y 的 toFixed(2)/toFixed(1)/round 与 r×100 的 5.33/5.3/0.0533 等变体；单选收集正确选项字母模式正则 `/(正确答案|正确选项|应选|答案是|选)\s*[:：是为]?\s*[A-D]\b/` + ≥8字正确选项整句（短选项如"正相关"不整句匹配防误杀）。
2. checkOutput：JSON提取（首`{`到末`}`）→ level===targetLevel → L3 必有非空 steps、L4 必有 solution.answer/process → L1~L3 对 hintBody+steps+guidingQuestion 扫泄露 token。
3. 重试与降级：不合格→messages 追加严厉提醒重试1次→仍不合格：L1~L3 degraded=true 直出 rag_snapshot 前2块知识原文+固定引导语（level 照常+1，log 记 degraded）；L4 degraded=true 直出题库 analysis+steps。LLM 网络级失败两次 → 502，不降级不给答案。
4. 注释写明边界：字符串检测防"照抄级泄露"，概念性重述由 System Prompt 层级铁律兜底。

## 八、前端设计

- **HintPanel.vue**：props `{question, session, studentAnswer, judgeResult}`，emit `refresh`。卡片 v-for 渲染 session.logs；tag 徽标 L1蓝"提示一·方向"/L2绿"提示二·关键条件与知识点"/L3橙"提示三·思路框架(含留白)"/L4红"完整解析"/降级灰"知识卡(离线直出)"；hintBody v-html 受限富文本；L3 steps 含 ❓ 的行套黄色留白底；底部 guidingQuestion 引导块 + 有帮助/没帮助。
- **按钮状态机**：【获取提示】currentLevel<3 可见，loading 文案"正在生成提示…"，=3 置灰"渐进提示已到顶"；【查看完整解析】始终可见，ElMessageBox.confirm("确认查看完整解析吗？…")后调接口，solutionUnlocked 后置灰"已查看"。L1~L3 卡片底部困惑输入框 + "按我的困惑重新提示"。
- **Chapter11View 接线**：onMounted `userId = loadLocal('userId') || genId()` 并 saveLocal；`fetchAllState()` 得 hintMap；习题卡片 ex-actions 之后插 `<HintPanel :question="ex" :session="hintMap[ex.id]" :student-answer="..." :judge-result="..." @refresh="fetchAllState" />`；提交答对后 HintPanel 隐藏获取提示按钮。现有"提交答案/仿真验证/查看解析"逻辑全部不动。
- **api/hint.js**：独立 axios 实例（不复用 islm.js），timeout 30s。

## 九、环境与启动

- `.env`：PORT=3001、DB_HOST/PORT/USER/PASSWORD/NAME=islm_platform、ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3、ARK_API_KEY=、ARK_MODEL=doubao-1-5-pro-32k-250115、**LLM_MOCK=true**（默认true，无key可跑通全流程；用户拿到方舟key后改false）、可选 MOCK_LEAK=true 验证降级。`.env.example` 同步样例，`.gitignore` 追加 `.env`。

## 十、实施顺序与验证
